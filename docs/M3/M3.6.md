# M3.6 · Chapter 6, Runes: level specs

Branch `m3-6-chapter-6`. This is **checkpoint 1**: the specs below wait for the
designer's approval before any level is built. They build on
`docs/M3/M3.md` → Chapter 6.

Decided *(Designer, 2026-10-02)*:
- **The pawn stands on a rune to read it.** Runes are floor tiles.
  `pawn.read()` gives the text of the rune under the pawn, or None when it
  isn't on one.
- **A rune's text is shown before the run,** on the tile's tooltip and in the
  Challenge panel, like a signpost's. What makes the code necessary is that
  one program has to work on every board (Chapter 2's precedent).
- **The string tools taught:** indexing, slicing, `len()`, `int()`, `in`, and
  the methods `.upper()`, `.lower()`, `.replace()`, `.strip()`,
  `.startswith()`, `.endswith()`, `.find()`, `.count()` and `.split()`.

## Already built, before the specs

Committed as `177e511`; `npm run check` passes.

- **Rune tiles and `pawn.read()`.** A rune is floor with text on it
  (`R: {tile: rune, text: "…"}` in a level's legend). Each board of a level
  can give the same symbol its own text through a variant's legend. `read()`
  costs no tick, and playback lights the rune. `look()` calls a rune ahead
  "rune". The board draws a stone slab; hovering it shows the text.
- **The Codex** has entries for `len()`, `int()` and the nine methods of text
  (`str.upper` and so on, listed under "Text"). Hovering `.upper` in code
  shows the entry once a lesson has taught it. The level checker applies
  "taught by then" to methods, as it does to built-ins.
- **Friendly errors for text:** a position past the end of the text, trying to
  change a character, `int()` on text that isn't digits, and a `None` from
  `read()` off a rune (it says the pawn isn't on one) for indexing, `len()` and
  methods. Joining a number to text with `+` mentions `str()` and f-strings.

## What Chapter 6 teaches, and what makes each part necessary

| Level | Trains | What makes it necessary |
|---|---|---|
| 6.1 The Runestone | `read()`, a variable holding text, indexing | the runes differ between boards; the second guard wants a letter, and the pawn has left the rune by then, so the text has to be kept |
| 6.2 Cut It Out | slicing | each rune starts with a label and the words differ in length, so no fixed positions work |
| 6.3 Smudged Runes | `strip()`, `upper()`, `lower()`, `replace()` | stray spaces, capitals and dashes that differ on every board |
| 6.4 Which Road? | `in` (and `startswith`, `endswith`, `find`, `count`) | a crossroads with pits on the wrong roads; only the rune says which road is safe |
| 6.5 Where the Rune Points | `int()`, `split()`, indexing the pieces | two numbers written as text, whose lengths change from board to board |
| 6.6 The Written Route *(mastery, optional)* | everything on text, `for` over pieces | a whole route written on the rune, with 2, 3, 4 and 5 legs |

Every board was checked with the real engine (`scripts/gen_runes.py probe`,
which prints counts only):
- each board can be solved on its own, and no board's own solution works on
  the other three (6.4: only the two "left" boards share one, since their
  layouts match);
- the smallest answer, counted in operations on the text, for each family of
  tools. "None" means nothing in the search of that family reached it:

| Guard | Only reading | + indexing | + slicing | methods | with split |
|---|---|---|---|---|---|
| 6.1 A (the whole text) | 0 | 0 | 0 | 0 | 0 |
| 6.1 B (a letter) | none | 1 | 1 | none | 1 |
| 6.2 A (after the label) | none | none | 1 | none | 1 |
| 6.2 B (the last letters) | none | none | 1 | none | 1 |
| 6.3 A (tidied, in capitals) | none | none | none | 2 | 2 |
| 6.3 B (small letters, dashes as spaces) | none | none | none | 3 | 3 |
| 6.5 first number | none | none | none | none | 1 |
| 6.5 second number | none | none | none | none | 1 |

  (6.5's number also has a clumsy answer of 3 operations using slicing and
  methods: dropping the last two characters, then the comma. `split()` is the
  neat way, and that is what the lesson teaches.)
- 6.4: of the questions the lesson teaches, only `in` tells the "left" boards
  from the rest with a whole word; `startswith`, `endswith` and `==` can't,
  because the word sits in a different place on every board.

Findings that shape the chapter:

- **Par can't force one string tool over another.** `text.replace("key:", "")`
  is a line too, so 6.2's slice is par but not forced. Each lesson teaches its
  tool; what is forced is the *need to read the rune and work on its text*.
- **Chained methods save lines.** `text.strip().upper()` is one line; doing
  it in steps costs a line more and earns fewer stars. 6.3's lesson shows a
  chain.
- **`split()` hands back a list**, which Chapter 7 teaches properly. The
  lesson only uses what the pawn needs: pick a piece by its number, and (in
  6.6) go through the pieces with `for`.
- **No chaser, no ice, no new obstacle.** Everything uses what's built.

## Proposed changes to the outline (for approval)

1. **5 levels + mastery, as outlined,** with these titles. Indexing moves into
   6.1 with reading, as the outline said ("reading a rune; indexing").
2. **6.4 teaches the five "ask the text" tools** (`in`, `startswith`,
   `endswith`, `find`, `count`) in one lesson, because they answer the same
   question. Only `in` is shown at work in the level.
3. **6.5 is the destination in numbers:** two numbers, a leg east and a leg
   north. Two-digit numbers on some boards make a fixed position fail.
4. **The mastery is a route written on the rune** (a letter for the turn, a
   number of squares), rather than "several runes", because the number of legs
   varies and so a loop over the pieces is needed.

## The levels

In every map `P` is the start, `G` the goal, `R` a rune, `#` a wall, `O` a pit,
and `A`/`B` a guard's gate. Every level has four boards; they differ in the
runes' text (and the gates' answers, or the goal).

### 6.1 · The Runestone

- **Trains:** reading a rune with `read()`, keeping its text in a variable, and
  indexing one character (the first).
- **Brief:** "A rune is a stone with writing on it. Stand on it, and your pawn
  can read it."
- **Board** (3×8, the same on every board):
  ```
  # G #
  # . #
  # B #
  # . #
  # A #
  # R #
  # . #
  # P #
  ```
- **The runes:** `ember` · `willow` · `oracle` · `tin`.
- **The guards ask:** at A, "What does the rune say?"; at B, "What is the first
  letter of the rune?"
- **Abilities:** `move`, `read`. **Rules:** none. **Par:** about 6 (a move, a
  read into a variable, a print, a move, a print, a move).
- **Must fail:**
  - typing board 1's answers (the other boards' guards refuse);
  - printing the whole text for both guards (guard B can't follow it);
  - reading again at the second guard (the pawn has left the rune: `None`).
- **Lesson** (on a lesson board with one rune): `read()` and `print()`; keeping
  the text in a variable; `text[0]`, positions counting from 0; a `run error`
  snippet reading off a rune.

### 6.2 · Cut It Out

- **Trains:** slicing: `text[a:b]`, from the start, to the end, and counting
  back from the end with a minus.
- **Brief:** "Every rune here starts with a label. The guards want only part of
  what it says."
- **Board:** as 6.1.
- **The runes:** `key:amber` · `key:willow` · `key:crimson` · `key:lantern`.
- **The guards ask:** at A, "What is the word after the label?"; at B, "What
  are the last three letters of that word?"
- **Abilities:** `move`, `read`. **Rules:** none. **Par:** about 6.
- **Must fail:** a fixed slice that suits one word (the others differ in
  length); the whole rune; the indexing from 6.1 alone (a letter at a time).
- **Lesson:** `text[2:5]`, `text[:3]`, `text[3:]`, `text[-2:]`, shown on a
  rune; a `run error` snippet taking a position past the end of the text.

### 6.3 · Smudged Runes

- **Trains:** methods of text: `strip()`, `upper()`, `lower()`, `replace()`,
  and chaining them.
- **Brief:** "The runes are smudged: stray spaces, wrong capitals, dashes for
  spaces. The guards want them tidy."
- **Board:** as 6.1.
- **The runes** (spaces matter): `␣␣Silver-Moon␣␣` · `Ghost-LANTERN␣` ·
  `␣iron-gate` · `OLD-bridge␣`.
- **The guards ask:** at A, "What does the rune say, in capitals, without the
  stray spaces?"; at B, "Now in small letters, with a space where each dash
  was?"
- **Abilities:** `move`, `read`. **Rules:** none. **Par:** about 6 (a chain is
  one line; separate steps cost more).
- **Must fail:** the rune as it is; capitals without stripping (the spaces are
  still there); one answer for both guards.
- **Lesson:** `upper()`, `lower()`, `strip()`, `replace("-", " ")`, shown on a
  rune; that a method makes a copy (the original text doesn't change); a chain;
  a `run error` snippet trying to change a character in place.

### 6.4 · Which Road?

- **Trains:** asking text a question: `"word" in text`, and `startswith()`,
  `endswith()`, `find()`, `count()`, with `if`/`elif`/`else`.
- **Brief:** "At the crossroads, two roads end in pits. A rune on the way says
  which road is safe."
- **Board** (9×9; the goal is at the end of the safe road, and the other two
  roads end in a pit; this is the "left" board):
  ```
  # # # # O # # # #
  # # # # . # # # #
  # # # # . # # # #
  # # # # . # # # #
  G . . . . . . . O
  # # # # . # # # #
  # # # # . # # # #
  # # # # R # # # #
  # # # # P # # # #
  ```
- **The runes and the safe road:**
  - "The old road to the left is the safe one." (left)
  - "Keep to the right, traveller. The other roads end in thorns." (right)
  - "Straight on is the only safe road." (straight on)
  - "Take the left road, friend, and fear nothing." (left)
  - No rune mentions both "left" and "right".
- **Abilities:** `move`, `turn_left`, `turn_right`, `read`. **Rules:** none.
  **Par:** about 8.
- **Must fail:** a guess (a wrong road is a pit: lost); testing the whole
  text for equality with one sentence.
- **Lesson:** `in`, then the four others on a rune; `if`/`elif`/`else` is
  already known; a `run lost` snippet taking the wrong road.

### 6.5 · Where the Rune Points

- **Trains:** text into numbers: `int()`, `split()` and a piece picked by its
  number.
- **Brief:** "The goal is somewhere out in the open. The rune says how far:
  first east, then north."
- **Board** (12×12, open, with the rune on the square ahead of the start; the
  pawn starts facing **east**; the goal is where the numbers lead):
  ```
  . . . . . . . . . . . .      (…the goal somewhere in here)
  P R . . . . . . . . . .
  ```
- **The runes:** `10,3` · `4,10` · `7,2` · `9,4` (a leg east, then a leg north).
- **Abilities:** `move`, `turn_left`, `read`. **Rules:** none. **Par:** about 5.
- **Must fail:** one board's numbers typed in; `move()` with the text itself
  (numbers in quotes are text); reading the first digit only (fails on 10).
- **Lesson:** `int("4")`, `"4,10".split(",")`, `pieces[0]`, shown on a rune;
  a `run error` snippet with `int()` on text that isn't digits.

### 6.6 · The Written Route *(mastery, optional)*

- **Trains:** everything on text: a route written on the rune, followed one leg
  at a time.
- **Brief:** "A rune writes out the whole route: L or R for the turn, then the
  number of squares. Follow it to the goal."
- **Board** (11×11, open; the pawn starts facing north with the rune one square
  ahead; the route starts from the rune):
  ```
  . . . . . . . . . . .
  . . . . . . . . . . .
  . . . . . . . . . . .      (…the goal is where the route ends)
  . . . . . R . . . . .
  . . . . . P . . . . .
  ```
- **The runes:** `R4,L3` · `L3,R5,L2` · `R2,L4,R2,L1` · `R1,L5,R2,L2,R1`
  (2, 3, 4 and 5 legs; the goals are all different).
- **Abilities:** `move`, `turn_left`, `turn_right`, `read`. **Rules:** none.
  **Par:** about 7 (a step onto the rune, a loop over the pieces, a choice of
  turn, and the walk).
- **Must fail:** one board's route typed in; a loop with a fixed number of
  legs (the boards have 2 to 5).
- **Lesson:** `for piece in text.split(","):`, a piece's first character and
  the rest of it, `find()` and `count()` for the curious; no new idea beyond
  putting the chapter together.

## The promotion *(Designer, 2026-10-02)*

**Moved to the design pass (M3.7)** *(Designer, 2026-10-02)*: after playing the
levels, the designer chose to build the ceremony and the knight skin there, in
the new look, so M3.6 ships the levels only. What follows is the plan M3.7
starts from. One note added: **once the knight is unlocked it must be
selectable in the menu** (Settings), not only in free play.

The end of Chapter 6 celebrates the promotion from pawn to knight, and the
knight becomes an unlockable skin (`DESIGN.md` §8). Approved with the levels:

- **Trigger:** once, automatically, the first time 6.1 to 6.5 are all solved.
  The mastery (6.6) stays optional and doesn't gate it. The Chapter 6 heading in
  the level list can replay it.
- **The ceremony** is a full-screen moment (`#/promotion/pawn`), not a modal. It
  celebrates, sums up what the pawn tier taught (from the Codex), shows the
  knight, and teases Chapter 7. Built in the current style; the design pass
  (M3.7) redraws it.
- **A piece is its rules, a skin is its look.** The knight skin is cosmetic: on
  every Pawn-tier level the piece still moves like a pawn. The knight's real
  L-moves arrive with Chapter 7.
- **Unlocking:** the knight is unlocked when Chapter 6's five core levels are
  solved. The rule is worked out from the saved progress, so Reset progress locks
  it again. A "promotion seen" record keeps the ceremony from repeating.
- **Using it:** Settings gets a **Piece** choice (pawn or knight) that works on
  every level. A level's own `piece` still decides the rules. Free play's skin
  gallery comes after M4.
- **To build in M3.7,** in the new style:
  - `src/skins.ts` (new): a registry of skins (pawn, knight) with each drawing,
    moved out of `board.ts`, and the unlock rule;
  - a `skin` setting in `src/settings.ts` (kept to what is unlocked) and a Piece
    choice in `src/ui/settingsDialog.ts`;
  - the "promotion seen" record in `src/progress.ts`;
  - the ceremony screen and its replay from `src/ui/levelSelect.ts`, with a route
    in `src/app.ts`;
  - a `promotion` entry on Chapter 6 in `levels/chapters.yaml`;
  - tests: vitest for the registry, the settings and the unlock rule, and an e2e
    check for the ceremony and the Piece setting in the pre-merge pass.

## Decided *(Designer, 2026-10-02)*

- **6.6 goes through `split()`'s list with `for`.** Chapter 7 teaches lists
  properly, but a route with a fixed number of legs would need no loop. The
  lesson teaches only what the pawn needs: a piece by its number, and `for`
  over the pieces.
- **6.5's board is 12 by 12,** so two-digit numbers appear and a fixed position
  can't read them. Not chosen: a smaller board with one-digit numbers.

Par stays provisional until the references are written blind.

## Built

The specs are approved as written *(Designer, 2026-10-02)*. Build order:
`scripts/gen_runes.py`'s writer, then the levels, solutions, lessons and chapter
entry. The promotion and the knight skin moved to M3.7.

**Levels, solutions and lessons: built.** `scripts/gen_runes.py` writes
`levels/ch06/`, `solutions/ch06/` (a reference, wrong attempts and a note for each
level) and prints only counts. `lessons/ch06/` is written by hand, and Chapter 6
is in `levels/chapters.yaml`.
- **How a reference is written:** a guard's answer is searched as an expression
  over the rune's text, using only the tools the lessons have taught by that level;
  the walk comes from the board's geometry; conditions come from the tools a lesson
  teaches; the number and turn expressions of 6.5 and 6.6 are checked on legs the
  level doesn't have. The few fixed lines of code, the hints and the notes are
  stored in ROT13.
- **Pars match the specs:** 6, 6, 6, 8, 5 and 7 lines. Every reference solves all
  four boards with three stars.
- **Wrong attempts**, each checked to fail:
  - 6.1 to 6.3: one board's answers typed in, the whole text for every guard, and
    reading again after leaving the rune (an error: the pawn is no longer on it);
  - 6.4: one board's road typed in, and testing the whole text for equality;
  - 6.5: one board's numbers typed in, the text without `int()` (an error), and
    reading one digit only;
  - 6.6: one board's route typed in, and a loop with a fixed number of legs.
- **The lessons teach every tool:** 6.1 `read()` and indexing; 6.2 slicing and
  `len()`; 6.3 `strip`, `upper`, `lower` and `replace`; 6.4 `in`, `startswith`,
  `endswith`, `find` and `count`, with a `run lost` snippet at a pit; 6.5 `int()`
  and `split()`; 6.6 `for` over the pieces.
- `levelgen.main` now holds the command line that `gen_while.py` and
  `gen_runes.py` share.

Not built here: the promotion ceremony and the knight skin, which moved to M3.7 (above).
