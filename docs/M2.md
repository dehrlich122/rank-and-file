# M2 · Feedback depth: plan and decisions

Branch `m2-feedback-depth`. `DESIGN.md` §7 lists M2 as: tiered hints, AST
constraints, hidden variants, par/stars, the idiomatic-solution reveal and
progress saving. A minimal AST check already shipped in M1.

## Decisions *(Designer, 2026-09-26)*

| Topic | Decision |
|---|---|
| Hints | Available **any time**, one tier at a time (nudge → concept reminder → partial example). Opened tiers stay visible. |
| Stars | **★ solved · ★ within the line par · ★ no hints opened.** Three stars are always possible. Opening a hint gives up the third star for that level. |
| Hidden variants | **Built in M2**, with one practice level outside the curriculum to try by hand. Chapter 1 can't use them: sequencing solutions are meant to be hard-coded. Chapter 3 onwards will. |
| Giving up | Once every hint is open and **3 more runs** have failed, a "Show me a solution" button appears, behind a confirm step. The level counts as *solved with help*, with no stars, until you solve it yourself. |

Defaults, not asked (say if you want them different):

- Progress is saved in the browser: solved levels, best stars, hints opened, and **your code for each level**. It survives reloads.
- Every level stays open: nothing is locked behind the previous level.
- Settings gets **Reset progress**, confirmed inside the page (never a browser pop-up).

## How each part works

**Scoring lives in the engine.** `run_level` takes how many hints were opened
and returns the stars along with each star's reason. The UI draws them. `par`
is validated like every other level key (`{lines: N}` for now; moves and
required idioms can come later).

**Hints** appear in the Challenge panel as a "Show a hint (1 of 3)" button. A
run that doesn't solve the level also offers "Need a hint?" on its outcome
card. Before the first hint opens, a note says what it costs.

**The idiomatic solution** is shown after solving (or after giving up):
"Compare with an idiomatic solution" opens your code and the reference
solution side by side, with its note (`solutions/<chapter>/<id>.md`).
Solutions are **loaded lazily**: each level's solution is a separate file,
fetched only when you ask to see it, never part of the main bundle.

**Several cases** *(reworked in QA-016)*. The first design ran the code on
"hidden boards" after the visible one was solved. In play-testing it felt like
a bait-and-switch: the goal seemed to move once you reached it. Now:

- **A hidden goal.** The map marks the squares it might be on with `?`, and
  shows no flag. The code runs once per `?` square and must reach the goal
  every time. Afterwards each square shows ✓ or ✗, and a row of buttons
  above the board replays any case.
- **Other maps** (`variants:` in the level file) still work the same way,
  for later levels whose layout varies. Players see them as "board 2", ….
- The pawn gains `at_goal()` (locked unless a level unlocks it) so a
  program can tell where it is.
- The practice level, **Blindfold**, lives in `levels/practice/`, in the
  Testing ground (`curriculum: false`). Chess feint terms (Decoy, Deflection)
  are kept for level titles and flavour.

Along the way:

- e2e failure screenshots now blur hints and solution notes as well as
  editors. During development, one screenshot showed a note.
- A fresh e2e page load (`?fresh=`) starts with no saved progress;
  `{ reload: true }` keeps it.

The `/simplify` pass (four reviews: reuse, simplification, efficiency, altitude):

- **Fixed a bug it found.** A run's result was saved when playback reached
  its last frame, so replaying or jumping to the end counted one failed run
  again and again towards "Show me a solution". Leaving mid-animation could
  also lose a solve. Results are now saved once, when the run finishes. An
  e2e check covers it.
- `ui/help.ts` holds the hints, giving up and the comparison offer, which
  `levelView.ts` had been doing piecemeal.
- `ui/dialog.ts` has the shared modal, title-row and confirm-step helpers.
- Progress no longer stores `solved`: at least one star means solved.
- The Testing ground is marked `curriculum: false` in `chapters.yaml`, not
  by being chapter 0. "Next level" follows that file's order.
- Engine: one wording helper (`words.count`), and `World.at_goal()` used for
  the goal objective.
- e2e: shared `clickButton`/`hasButton`/`editorText`/`challengeTab` helpers,
  and no fixed sleeps.

Skipped on purpose:

- Moving the give-up rules into the engine. They're about the player's
  progress, not the board.
- Cheaper hidden-board reruns and batched saves while typing. Not worth it
  at this size.

## Rollup *(2026-09-26)*

M2 is **complete**. The designer's manual test list passed, QA-016 was
fixed and verified, and PR #3 was merged into `main`.

What M2 added:

- **Saved progress:** solved levels, best stars, hints opened, and each
  level's code survive a reload. Settings → Reset progress starts over.
- **Stars, scored by the engine:** solved, within the line par, no hints
  opened. The par is shown in the Challenge panel before you start.
- **Tiered hints,** one at a time, with their cost shown first.
  "Need a hint?" on a failed run takes you to them.
- **Compare with an idiomatic solution** after solving: your code, the
  reference solution and a note. Solutions load lazily and never enter the
  main bundle (`npm run check:bundle`).
- **Giving up:** "Show me a solution" after every hint is open and 3 more
  runs have failed, with a confirm step. The level is then marked
  "Solution seen".
- **Several cases:** a hidden goal on ? squares (the code runs once for
  each), or other whole maps. There's a per-case row and ✓/✗ marks, and
  `pawn.at_goal()` is new.
- **The Testing ground:** levels outside the curriculum, starting with
  Blindfold.

Quality along the way:

- Two `/simplify` passes, which found and fixed three bugs: runs
  double-counted on replay, overlapping replays, and a drawing bug on
  failed squares.
- The e2e harness fails fast on a crashed page, and hides hints and
  solution notes in failure screenshots.
- Checks at the merge: 50 vitest, 169 pytest, lint, the bundle check, and
  102 e2e checks, all passing.

Carried into M3:

- Chapters 2–5 complete the Pawn tier. The loops chapter onward can use
  ? squares and other maps to force general solutions.
- An open curiosity: the occasional e2e stall when a level loads. It
  predates M2; see `docs/QA.md` and the project notes.
