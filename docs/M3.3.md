The specs give each level's concept, map, rules, par and boards. They never
give solution code. References, wrong attempts, hints and solution notes

## What Chapter 3 teaches, and what makes each part necessary

| Level | Trains | What makes it necessary |
|---|---|---|
| 3.1 The Grand Staircase | `for` and `range()`: repeating a block of lines | a line limit: copied out, the stairs take 24 lines, and the limit is 7 |
| 3.2 The Crooked Stair | a loop's lines run afresh each round, so a count inside the loop gets a new answer every time | three boards whose steps are all different, and a line limit |
| 3.3 The Spiral Walk | the loop's variable, and `range(start, stop, step)` | a walkway over pits, each stretch one square shorter than the last, and a line limit |
| 3.4 The Clockwork Sentry | outpacing clockwork: a loop runs fewer new lines than the same moves copied out | a clockwork sentry that steps once for each new line of code |
| 3.5 Three Flights | loops inside loops | three flights of stairs meeting at corners, and a line limit |
| 3.6 The Clocktower *(mastery, optional)* | everything above, together, with a tight par | a spiral stair whose flights grow, and a clockwork sentry |

Two facts about the pawn shape the whole chapter:

- **`pawn.move(n)` walks any straight line in one line of code.** So a loop
  only pays when the repeated part turns. Every route here repeats a
  pattern with turns in it: steps, a spiral, flights.
- **`squares_ahead()` measures any walled corridor.** A loop can ask it how
  far to go each round. That's the point of 3.2, but it would let 3.3 and
  3.5 skip their ideas. So 3.3's walkway is over pits, which the count
  sees past, and 3.5's flights meet at corners, which a count can't turn.

## Proposed changes to the outline (for approval)

1. **No straight-corridor level.** The outline's 3.1 was "a long corridor
   under a tight line limit", but `move(n)` already walks a corridor in one
   line. 3.1 is a staircase instead, which was the outline's 3.2.
2. **A new 3.2: a loop that asks the board each round.** The same kind of
   staircase, but crooked, on three boards. It carries counting from
   Chapter 2 into loops (spaced review).
3. **Pits arrive in Chapter 3,** in 3.3. `docs/M3.md` places them in
   Chapter 4. The walkway needs them: over pits, the stretches can only be
   known from the loop's variable. 3.3's lesson shows a pit at work.
4. **No waypoints or gems.** In a corridor a waypoint adds nothing, since
   the route is the only way through. Gems are collected by walking over
   them, so how many a route collects is known ahead from the map (as
   decided in M3.2, change 6). Counting them waits for Chapter 4's
   `look()` and Chapter 5's counters.
5. **The mastery combines nesting, the loop's variable and clockwork.** The
   outline had "clockwork, waypoints and nested loops".
6. **A line limit can't be dodged with `;` any more.** Today the count is
   of physical lines. `;` puts several statements on one line, and a loop's
   body can sit on the loop's own line, so 3.1 copied out would fit on a
   single line. From now on each statement counts as a line, however it's
   written. No existing reference solution puts two statements on one
   line, so no level's par changes.
7. **The pawn keeps what it has learned.** Every Chapter 3 level unlocks
   `move`, `turn_left`, `turn_right`, `squares_ahead` and `wait`.

## The levels

In every map `P` is the start and `G` the goal, `#` is a wall and `O` a
pit. The pawn starts facing east unless a level says otherwise. Line limits
are par plus 2, as in QA-004.

### 3.1 · The Grand Staircase

- **Trains:** `for` loops and `range()`: repeating a block of lines.
- **Brief:** "A grand staircase climbs to the goal, six steps all the same.
  There's only room for 7 lines of code."
- **Map** (7×7):
  ```
  # # # # # . G
  # # # # . . #
  # # # . . # #
  # # . . # # #
  # . . # # # #
  . . # # # # #
  P # # # # # #
  ```
- **Rules:** at most 7 lines of code.
- **Par:** 5.
- **Must fail:** the moves copied out (24 lines, over the limit).
- **Lesson** (on a small lesson board, not the level's map):
  - `for step in range(3): print("Step", step)`: the indented lines run
    once for each number, and `range(3)` gives 0, 1 and 2.
  - A loop whose indented lines are a move and a turn: the pawn walks
    round a pillar, the block repeating as a whole.
  - A `run error` snippet: the line under the loop isn't indented.

### 3.2 · The Crooked Stair

- **Trains:** a loop's lines run afresh each round, so a count inside the
  loop gets a new answer every time.
- **Brief:** "Three crooked staircases, no two steps alike, and one program
  for all of them. There's only room for 7 lines of code."
- **Boards** (10×8 each; five steps on every board, their treads and
  risers different):
  ```
  board 1               board 2               board 3
  # # # # # # # . . G   # # # # # # # . . G   # # # # # # # # . G
  # # # # # # # . # #   # # # # # . . . # #   # # # # # # # # . #
  # # # # # # . . # #   # # # # # . # # # #   # # # # # # . . . #
  # # # . . . . # # #   # # # # . . # # # #   # # # # . . . # # #
  # # . . # # # # # #   # . . . . # # # # #   # # # # . # # # # #
  # # . # # # # # # #   . . # # # # # # # #   # # # . . # # # # #
  . . . # # # # # # #   . # # # # # # # # #   . . . . # # # # # #
  P # # # # # # # # #   P # # # # # # # # #   P # # # # # # # # #
  ```
- **Rules:** at most 7 lines of code.
- **Par:** 5.
- **Must fail:**
  - a loop with board 1's lengths typed in (wrong on boards 2 and 3)
  - the moves copied out (20 lines)
- **Lesson** (on a lesson board: a corridor that turns right at every
  corner, its stretches of different lengths):
  - A loop that prints `pawn.squares_ahead()` each round, then moves that
    far and turns: a new answer every time.
  - A `run error` snippet: the same loop moving a fixed number of squares
    bumps a wall.

### 3.3 · The Spiral Walk

- **Trains:** the loop's variable, and `range(start, stop, step)`.
- **Brief:** "A walkway spirals in over a bottomless pit, each stretch one
  square shorter than the last. Step off it and you fall. There's only room
  for 5 lines of code."
- **Map** (8×7, pits all round; the pawn starts facing north):
  ```
  P . . . . . . .
  O O O O O O O .
  O O . . . . O .
  O O . O O . O .
  O O . O G . O .
  O O . O O O O .
  O O . . . . . .
  ```
- **Rules:** at most 5 lines of code.
- **Par:** 3.
- **Must fail:**
  - the moves copied out (14 lines)
  - a loop that walks the same length every round (falls in)
- **Checked:** the shortest program without the loop's variable is 13
  lines, well over the limit.
- **Lesson:**
  - `range(5, 0, -1)` printed: a countdown, since the third number is the
    step.
  - On a lesson board with a walkway over pits whose treads grow: a loop
    whose variable is how far to move.
  - A `run lost` snippet: the same walkway with a fixed move, and the pawn
    falls into a pit.

### 3.4 · The Clockwork Sentry

- **Trains:** outpacing clockwork: a loop runs fewer new lines than the same
  moves copied out.
- **Brief:** "A clockwork sentry waits on the gallery above the stairs.
  Every new line of code you write winds it one step closer."
- **Map** (9×7):
  ```
  # # . . . . . . .
  # # # # # # # # .
  # # # # # # . . G
  # # # # . . . # #
  # # . . . # # # #
  . . . # # # # # #
  P # # # # # # # #
  ```
- **The sentry:** a clockwork patrol (gear badge) on c7, 8 squares from the
  goal. Its route runs along the gallery to the goal, then down the stairs
  to a1, and back. It steps once each time a line of code runs for the
  first time.
- **Rules:** none; the sentry does the forcing.
- **Par:** 5.
- **Must fail:** the moves copied out (16 lines): the sentry reaches the
  goal first and comes down the stairs.
- **Checked:** a 5-line loop gets through with the sentry still 3 squares
  short of the goal.
- **Lesson** (on a lesson board with a clockwork patrol, like the Testing
  ground's Clockwork):
  - A loop of moves: the patrol's gear counts only lines running for the
    first time, and it stands still while the loop repeats.
  - A `run lost` snippet: the same moves copied out, and the patrol catches
    the pawn.

### 3.5 · Three Flights

- **Trains:** loops inside loops.
- **Brief:** "Three flights of stairs, each turned a quarter from the last,
  with a landing between. There's only room for 10 lines of code."
- **Map** (9×9):
  ```
  # # # . . . # # #
  # # . . # . . # #
  # . . # # # . . #
  . . # # # # # . .
  . # # # # # # # .
  G # # # # # # . .
  # # # # # # . . #
  # # # # # . . # #
  # # # # # P # # #
  ```
- **Rules:** at most 10 lines of code.
- **Par:** 8.
- **Must fail:**
  - a separate loop for each flight (15 lines)
  - the moves copied out (42 lines)
- **Lesson:**
  - A loop inside a loop, printing both loops' numbers: the inner loop runs
    all the way through on every round of the outer one.
  - On a lesson board: two short flights of stairs with a landing between,
    climbed with one loop inside another.

### 3.6 · The Clocktower *(mastery, optional)*

- **Trains:** Chapter 3 mastery: loops inside loops, a loop's variable and
  clockwork, together.
- **Brief:** "A spiral stair winds up the clocktower, each flight one step
  longer than the last. A clockwork sentry is coming down to meet you."
- **Map** (8×10):
  ```
  # # # . . . # #
  # # . . # . . #
  # . . # # # . .
  . . # # # # # .
  . # # # # # . .
  G . # # # # P #
  # . . # # # # #
  # # . . # # # #
  # # # . . # # #
  # # # # . . . #
  ```
- **The sentry:** a clockwork patrol on g1, 10 squares below the goal on the
  next flight down. Its route climbs to the goal, then follows the spiral
  all the way to the start, and back.
- **Rules:** none; the sentry does the forcing.
- **Par:** 8.
- **Must fail:**
  - a separate loop for each flight (17 lines): caught
  - the moves copied out (30 lines): caught
- **Checked:** an 8-line program gets through with the sentry still 2
  squares short of the goal.
- **Lesson:** an inner loop whose count comes from the outer loop's
  variable, shown with prints (see open question 3).

## Engine and tools

1. **Each statement counts as a line** (change 6), for `max_lines` and for
   the par star. Clause headers such as `else:` count too, ready for
   Chapter 4. The rule's wording in the Challenge panel says so.
2. **`range()`'s Codex entry** gains `range(start, stop, step)` and counting
   down.
3. **Friendly errors for common loop mistakes:**
   - `for n in 5:`: "To repeat something 5 times, use `range(5)`."
   - `range(7 / 2)` or `range("3")`: `range()` needs whole numbers.
   - "Did you mean" should prefer the player's own names. Today a
     misspelled loop variable (`stpe` for `step`) suggests `type`.
4. **Chapter 3 in `chapters.yaml`,** "Marching Orders", after Chapter 2.
   2.6's "Next level" then leads to 3.1.
5. **A blind generator in `scripts/`** (`gen_loops.py`), answering the
   question from M3.2 about moving the generator there. `solve.py` finds
   each level's route, the only way through. The generator replays that
   route in the fewest lines, using loops, a loop's variable, counting and
   loops inside loops. It writes the references and wrong attempts and
   prints only counts. It checked every map above.

No UI work is expected: pits, clockwork patrols and several boards all
exist already.

## Open questions

1. **Pits in Chapter 3** (change 3). Recommended: yes.
2. **A loop variable that isn't used.** Python's habit is `_`
   (`for _ in range(6):`). Recommended: the lessons name it (`step`), the
   references use `_`, and 3.1's solution note explains why.
3. **The mastery's lesson.** Its idea, an inner loop's count taken from the
   outer loop's variable, isn't taught earlier. Recommended: its lesson shows
   it with prints, and the level is the puzzle. The alternative is to leave
   it for the player to discover.
4. **Titles and briefs,** as written above, or changed.

  a flight reads "stairs, then landing".
- **Every wrong attempt fails as intended:**
  - copied out: over the line limit (3.1, 3.2, 3.3, 3.5), or caught by the
    sentry (3.4, 3.6)

    the edge of the board on 3.3 (the spec expected a fall)
  - a separate loop for each flight: over the limit on 3.5, caught on 3.6
- **Lessons** as specified. 3.4's copied-out snippet carries comments, so
  it can't match any level's reference solution: the bundle check looks for
  every reference's text in the main bundle, and caught the first version.
