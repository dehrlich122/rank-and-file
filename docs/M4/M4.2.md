# M4.2 · The level editor, I: the board: spec

The spec for M4.2 (`docs/M4/M4.md` has the plan and the decisions this builds on).
It's for the designer to approve before anything is built. Nothing in it is built yet.

*(Designer, 2026-10-07)*: the editor is for players and the designer. Its levels can be
exported and shared (sharing is M4.3). **The engine is the only judge.** One YAML format.

**Branch:** `m4-2-editor`, from `main` (M4.0 and M4.1 are merged).

## What M4.2 is, and isn't

M4.2 is everything you can *draw and set on a board*, plus saving, test-play and files.
M4.3 is the *rules around it* and sharing.

| In M4.2 | In M4.3 |
|---|---|
| Size up to 12×12; tiles; start and facing; goal or `?` squares | Objectives (`collect`, `capture`, `say`) |
| Enemies: kind, start, route, loop, clock, armoured | Constraints (`max_lines`, required/banned constructs, `max_numbers`) |
| Text: signs, runes, gate questions and passphrases, timed-gate timing | Par, hints |
| Planks to start with; which abilities the piece has | Other boards (variants) |
| Title, brief, "what it trains" | The solvability check |
| Undo/redo; **My levels** (drafts saved in the browser) | Sharing: link, code, the author's solution |
| Test-play in the real level screen | "Save to the repo" (dev server only) |
| Export and import `.yaml`; copy a lesson level | |
| The start menu's Level Editor entry switches on | |

A level made in M4.2 plays with the default objective (reach the goal, plus any waypoints
on the board), no line limit, no par and no hints. Test-play shows that honestly: no stars
to earn, no "Show me a solution" (there is no solution yet; the author's comes in M4.3).

## Added on my own judgment

You said to use my best judgment on question 6. These are in the first version, and each is
small:

- **A fill for walls:** Shift+arrows (or Shift+drag) select a rectangle; Enter fills it with
  the current tool, and Erase clears it. Hand-drawing a room square by square is tedious.
- **Coordinates are always on** (a1 style, as in a level): the editor uses chess names for
  every square, error and status line, so no toggle.
- **Flip and rotate the whole board** are *not* in, because they'd change which way the
  pawn faces and what the text says. Resizing keeps what fits and drops what doesn't, with
  a confirm step if that would lose something.
- **A "Clear board" button** in the New menu (with a confirm step).
- **Duplicate level** in My levels, because remixing your own level is the commonest thing.
- **Reset to the copied lesson level** isn't offered; copy it again.

## Decisions to confirm

Each has a recommendation; the first is what I'll build unless you say otherwise.

### 1. Layout: three columns, shown on a dev page first

The level screen is already three columns (`learn` / `board` / `code`, the board in the
middle at a fixed `--side-col` either side). The editor reuses that grid, so the board
sits where it does in a level and test-play feels like the same room:

```
┌ toolbar: New · Undo · Redo · Test-play · Export · Import · size 8×8 ─────────┐
│ Palette        │            the board              │ Properties              │
│ ▸ Floor        │   (the real BoardView, with       │ Level │ Square │ Enemy  │
│   Wall         │    a cursor and a selection)      │ title, brief, trains,   │
│   Sign …       │                                   │ abilities, planks …     │
│ Start · Goal   │   status line: "c4 · wall"        │ Problems (2) ▾          │
│ Enemies …      │                                   │                         │
└────────────────────────────────────────────────────────────────────────────┘
```

- **Palette (left):** tools, listed from the sprite registry (`TILE_SPRITE`,
  `ENEMY_SPRITE`) plus Start, Goal, Hidden goal (`?`), Erase and Select. Each shows its real
  sprite. A tile or enemy added to the registry appears here with no editor change.
- **Properties (right):** three tabs.
  - **Level:** title, brief, trains, abilities, planks, facing, size.
  - **Square:** the selected square's text (a sign's words, a rune's, a gate's question
    and passphrase, a timed gate's `every`/`open`/clock).
  - **Enemy:** the selected enemy's kind, start, route, loop, clock, armoured.
  - **Problems** sits under the tabs on every tab (see 3).
- **Narrow windows** stack the columns, as the level screen does.

*(M3.7 rule)* New layout, so it goes on a dev page first: `design/editor.html`, with the
real sprites and `BoardView`, static, in both themes, and I'll show a screenshot of two
takes: this three-column one, and one with the properties as a floating panel beside the
selected square. The editor goes into the game only after you pick. **Step 0 stops there.**

### 2. The editor draws from its own draft; the engine still judges

The engine can only describe a level that's valid (`loadLevel` fails otherwise), but a
half-made level is invalid most of the time: no start yet, an enemy on a wall. So:

- The editor keeps a **draft** (below) and draws the board from it straight away.
  `draftToLevelInfo()` fills the same `LevelInfo` the board draws from. It copies data
  (tiles, texts, enemies); it applies **no rules**.
- After each edit (debounced about 150 ms) the draft is exported to the level format and
  sent to `loadLevel`. The engine's answer is the only verdict: "valid" or its error.
- **A guard against the two readings drifting apart:** a vitest imports every level in
  `levels/`, converts it to a draft and back, and checks the draft's drawing data equals
  what the engine describes (tiles, signs, runes, gates, timed gates, enemies, start,
  goal, `?` squares, planks). The same test proves import and export round-trip.

### 3. Errors where they belong: a small engine change

`LevelError` carries only a message, and the editor must put it on a square, an enemy or
a field. Parsing the message ("enemy 2: …") would be fragile, so:

- `LevelError` gains an optional **`at`**: `{ square?: "c4", enemy?: 2, field?: "title" }`
  (an enemy that starts on a wall has both the enemy and the square). Message wording
  doesn't change.
- I'll set `at` at the raise sites the editor can reach (about 25 of the 66): no start or
  goal, enemy errors, a text missing, a timed gate's timing, the start square attacked, and
  so on. Any other error carries no `at` and shows in the Problems list under the board.
- `bridge.load_level` returns `{ ok: false, error, at }`; `protocol.ts` mirrors it.
- The editor marks the square or enemy with a problem ring (a symbol and an outline, never
  colour alone), and the Problems list jumps to it. Errors that don't depend on the edit
  just made (the level was already broken) stay until fixed.
- Pytest: for each error the editor can reach, `at` names the right place.

### 4. Two more small engine changes

- **`lesson` and `chapter` become optional** in `parse_level` (defaults: none, 0), and
  `trains` may be empty, because an editor level has no lesson file. The level checker
  (`test_levels.py`) still demands them of every repo level, so curriculum levels can't
  lose theirs by accident.
- **`editorOptions`**, a new request, returns what the engine allows: each piece's
  abilities, tile kinds and which details each takes (`TILE_DETAILS`), enemy kinds and
  their keys (`ENEMY_KEYS`), clocks, strategies, facings, and the board size limit. The
  editor builds its choices from it, so it never keeps its own copy of a rule. Added to
  `Requests`, `handlers` and `bridge.py`, as the CLAUDE.md checklist says.
- **A size limit** in `parse_map`: at most 12 squares a side (a test confirms every repo
  level fits). Shared levels in M4.3 get the same cap.

### 5. The draft, and saving it

```ts
interface Draft {
  id: string;            // "my-<random>", unique per browser
  title: string; brief: string; trains: string;
  piece: "pawn";         // only the pawn exists until M5
  width: number; height: number;
  cells: Cell[][];       // cells[y][x]; y = 0 is the bottom rank
  start: Pos; facing: Facing; planks: number;
  goal: Pos | null; spots: Pos[];       // a goal, or ? squares
  enemies: DraftEnemy[];
  api: string[];
  extra: Record<string, unknown>;       // keys M4.2 doesn't edit, kept as they were
}
```

- A cell is a tile kind plus its details (text, passphrase, question, timing).
- **`extra` keeps what M4.2 can't edit.** Importing a file with hints, constraints, par,
  objectives or variants doesn't lose them: they're written back on export and sent to the
  engine as they came, and M4.3 will edit them. (If an edit makes a variant impossible,
  the engine says so, like any other error.)
- **Saved in `localStorage` under `rank-and-file:editor`**, apart from curriculum progress
  (`src/progress.ts`), written through `src/storage.ts`, so Reset progress doesn't touch your
  levels, and a "Delete all my levels" in Settings is separate and asks first. Autosaves on
  each edit. A level's id is its key.
- **Export** writes the draft in the level format with `yaml`'s `stringify`: the map as a
  block of text like the repo's files, the legend built from the cells (letters assigned
  in a stable order). **Import** reads a `.yaml` file (YAML 1.1, as `content.ts` does),
  converts it to a draft, and asks the engine. A file the engine refuses opens anyway,
  with its errors shown, so you can fix it (unless it's unreadable YAML, or over the size
  cap: 64 KB).

### 6. Painting, selecting and the keyboard

- **Mouse:** click or drag to paint with the current tool; one drag is one undo step.
  Click the start, goal or an enemy to select it; drag it to move it. Right-click erases.
- **Single things move, they don't multiply:** there's one start and one goal; placing
  either again moves it. Placing a goal clears the `?` squares and the other way round
  (the engine allows only one of the two), with a note in the status line.
- **Enemies:** pick the kind, click a square to place it. To draw a patrol's route, select
  it, choose "Route", and click its corners; the editor accepts only straight lines along
  a rank or file, as the engine does, and shows the dotted route as the board will.
  Rooks and bishops have no route.
- **Keyboard (one tab stop on the board):**
  - Arrow keys move the cursor; the status line, an `aria-live` region, says the square
    and what's on it ("c4 · wall · Enter to paint").
  - Enter or Space applies the current tool; Delete or Backspace erases.
  - `1`–`9` choose tools in palette order; `[` and `]` cycle them. `R` rotates the
    start's facing; `Shift`+arrows extend a rectangle from the cursor, and Enter fills
    it with the current tool.
  - Ctrl+Z undo, Ctrl+Shift+Z / Ctrl+Y redo (in a text field they stay the field's own).
  - Esc closes a panel or dialog first; with nothing open it opens Settings, as elsewhere.
- **Undo/redo:** a stack of draft snapshots (100 deep). A drag, a typing burst in one field
  and a route are each one step. Switching levels or leaving clears the stack.
- **Reduced motion and both themes** work as elsewhere: the cursor and rings are static
  outlines; the sprites are the registry's.

### 7. Test-play uses the real level screen

`mountLevel` gets a `testPlay` option, and the source is built from the draft:
`{ id, title, trains, mastery: false, lesson: "", data: <exported level> }`.

- No Learn tab or pager (there is no lesson): it opens on **Challenge**.
- No hints, no "Show me a solution" and no stars panel; the outcome says solved or not.
- Nothing is written to curriculum progress: no best stars, no crowns, no promotion, no
  "next level". Code you type is kept in the session only. A "← Back to the editor" button
  replaces the crumb.
- The Codex, the Challenge panel, the speed control, sound and the skin all work as in a
  level. Breaking a rule the engine knows shows its normal message.
- If the draft has Problems, "Test-play" is disabled with the first problem as its reason.

### 8. My levels, and the entry points

- Route **`#/editor`** is My levels: a list (title, size, last edited, a small board
  thumbnail), **New level**, Import, and for each: Open, Duplicate, Export, Delete (a
  confirm step in the page, never `confirm()`). Route **`#/editor/<id>`** opens a draft.
- **New level** offers: a blank board (8×8, start bottom-left, goal top-right), or **copy
  a lesson level** (pick from the chapters you can see in Lessons).
- **Copying a lesson level** copies the board (map, legend, enemies, start, planks), the
  piece and its abilities, and the rules into `extra`. It **never copies hints, the starter
  code, the lesson, the reference solution or its note** (no spoilers), and the copy is
  not marked `mastery`. Everything it copies is already shown on that level's own screen.
- The start menu's **Level Editor** entry switches on and opens `#/editor`.
- Crumbs: `My levels` / title. The document title follows.

### 9. Sound

Menu ticks and confirms in My levels, the palette and dialogs reuse M4.1's existing sounds
(`menu_tick`, `menu_choose`). Painting and erasing stay silent for now (a drag would be a
machine gun at 4×); a placing sound is a possible later addition.

## Tests

- **vitest:** the draft model and its editing functions (paint, move, resize, erase;
  single start and goal; goal ↔ `?`); undo/redo; export/import; the round trip over every
  level in `levels/`; the saved-drafts store (corrupt data reads as empty).
- **pytest:** `at` on each reachable error; optional `lesson`/`chapter`; `editorOptions`
  agrees with `TILE_DETAILS`, `ENEMY_KEYS`, `CLOCKS` and the pieces; the size cap, with
  every repo level inside it.
- **e2e** (in the pre-merge pass): open the editor from the start menu; paint a board by
  keyboard and by mouse; an invalid draft shows a ring and a Problems entry and disables
  Test-play; fix it; test-play to a solve with the real level screen; Back returns to the
  same draft; export then import gives the same board; a copied lesson level has no
  hints; Reset progress leaves My levels alone. Checks never type or print a level's
  solution; they use hand-made levels on blank boards.

## Left out on purpose

Objectives, constraints, par, hints and variants (M4.3); sharing and the author's solution
(M4.3); the dev-only "Save to the repo" (M4.3); difficulty and tier tags (M4.4); a
tile or enemy that doesn't exist yet in the engine (an editor never adds rules); the
mobile layout; CRT scanlines.

## Step 1 as built *(2026-10-08)*

**Engine** (`engine/rankfile/levels.py`, `bridge.py`; tests in `engine/tests/test_editor_levels.py`):
- `LevelError.at` and the `_locate` helper. The sites the editor can reach name their place: no goal, title, abilities,
  start, size, each enemy's problems (with the square, for "not on open ground"), the start square under attack
  (the square and the attacker), legend details (by symbol), and the other boards, constraints, par and objectives (by
  field). The enemy parser is now one function per enemy, so every error in it names the enemy.
- `chapter`, `lesson` and `trains` are optional; `MAX_SIDE = 12`; `editor_options()` and the `editorOptions` request.
- `loadLevel`'s refusal carries `at` (`protocol.ts` mirrors it).

**Editor data** (`src/editor/`):
- `draft.ts`: `Draft`, `Cell`, `DraftEnemy`, `blankDraft`, `draftToLevelInfo`, the square-name helpers.
  An enemy keeps only the keys its file has, so reading a file never "fixes" it silently.
- `levelData.ts`: `levelDataToDraft` / `draftToLevelData` / `draftToYaml` / `yamlToDraft`. The legend is rebuilt from the
  cells; a symbol stays what it was where it can, and **symbols that other boards (variants) use are never reused for
  something else**. `ImportError` is for a file that can't be held as a draft at all; engine problems still open.
  YAML is read and written as 1.1, like the checker, so "yes" and "4" survive.
- Tests: `levelData.test.ts` (31 cases) and `roundtrip.test.ts`, which sends every level in `levels/` through a draft and
  `scripts/compare_levels.py`: the engine must describe the rewritten level exactly as the original, and the draft's
  drawing data must equal the engine's. It prints counts and field names only. It bites: breaking the goal in
  `draftToLevelInfo` makes 42 of 45 levels differ.

**Not drawn from the draft:** the squares a rook or bishop attacks (`attacked`), which is a rule. Step 2 draws from the
engine's own description whenever the last check passed for the current draft, and from the draft otherwise.
