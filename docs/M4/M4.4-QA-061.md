## What it is

Free Play's Sandbox row stops opening the bare screen of M4.4 (an empty 8 × 8, a code box, Run, only the abilities
of solved lessons). It opens a **scratch level**: a level of the player's own that is never listed, named or
published. They write code against it on the real level screen (the editor's test-play), and change its board in
the real level editor. Nothing new is built for it: it is the editor and the level screen, opened a fifth way.

| In | Out |
|---|---|
| The scratch level, kept in this browser under its own key | A way to turn the scratch level into one of My levels (say if wanted) |
| The level screen opened on it (code, Run, playback, console) | A level with no goal (the engine refuses one; the scratch level has a goal like any level) |
| The editor opened on it, without what is about publishing | Any change to lesson snippets, which keep the engine's small open board (`loadSandbox`/`runSandbox`) |
| The old Sandbox screen, its layout rules and its hooks into the snippet player deleted | |
| One wording for "what the piece knows" in the engine (the `sandbox` flag goes) | |

## Decided without the designer (2026-11-16)

1. **Where it opens.** `#/free/sandbox` is the level screen on the scratch level, ready for code, as the old Sandbox
   was: one click from the hub to typing. "Change the board" in its toolbar opens the editor on the scratch level
   (`#/free/sandbox/board`); the editor's main button comes back. Crumbs: Free Play / Sandbox, and
   Free Play / Sandbox / Board.
2. **What it starts as.** An open 8 × 8, the piece at the bottom-left facing north, a goal at the top-right, and
   **every ability the editor offers switched on** (the complaint was "only gives access to some of the features";
   the editor has never tied abilities to progress). The player unticks what they don't want in the Level tab.
3. **What the editor hides for it:** everything about naming and publishing (title, brief, "what it trains",
   difficulty, Share, Export, Save to the repo, the solvability check, "← My levels"). What changes how the level
   plays stays (palette, size, facing, abilities, planks, squares and enemies, other boards, Problems, undo and
   redo, Clear board). It gains **Start over** (back to decision 2's board, with an in-page confirm step).
4. **What the level screen shows for it:** no Learn tab, no tier tag, no hints, no solution offer, no "Keep this as
   the level's solution", no stars kept. Reaching the goal says so plainly and offers "Change the board". The
   Challenge tab says what the Sandbox is in a line.
5. **What is kept.** The board and the code, in this browser, under the Sandbox's own key (not in My levels, so it
   is never in a list and can't be shared by mistake). A value the old Sandbox left under that key is ignored.
6. **Reset progress leaves the Sandbox alone**, as it leaves My levels: it now holds something the player made, and
   it has Start over. *(This undoes QA-057, an automated finding: "Reset progress clears the Sandbox's code".)*
7. **A scratch level the engine refuses** (say, its goal was erased) never dead-ends: `#/free/sandbox` opens the
   board editor, where Problems says what is wrong, as for any level.
8. **One wording.** The engine's `sandbox` flag goes, and every message says "In this level it knows: …" again
   (lesson levels never changed; lesson snippets said "Here it knows" for one day, since QA-058). The other choice,
   "Here it knows" everywhere, changes the text on every lesson level, so it waits for the designer.
9. **The hub row** reads "Sandbox · A board of your own to paint and code on", with the board's size where the
   count of abilities was.

**For the designer** (none blocks the merge): 6 (Reset progress and the Sandbox), 8 (the wording), and whether the
Sandbox should offer "Keep as one of my levels".
